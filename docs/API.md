# API and Integrations

The app has no REST API of its own. It integrates only with **Firebase** through the official FlutterFire SDKs, which handle transport (HTTPS/gRPC over TLS), auth headers, retries and offline queuing. No HTTP endpoints, headers or tokens are handled manually.

## Firebase Authentication (`firebase_auth`)

| Operation | SDK call | Wrapper |
|---|---|---|
| Observe session | `authStateChanges()` | `AuthRepository.watchUserId()` |
| Sign in | `signInWithEmailAndPassword(email, password)` | `AuthRepository.signIn` |
| Sign up | `createUserWithEmailAndPassword(email, password)` | `AuthRepository.signUp` |
| Sign out | `signOut()` | `AuthRepository.signOut` |

Error codes mapped (see `mapToFailure`): `invalid-credential`, `wrong-password`, `user-not-found`, `invalid-email` → `InvalidCredentialsFailure`; `email-already-in-use` → `EmailInUseFailure`; `weak-password` → `WeakPasswordFailure`; `network-request-failed` → `NetworkFailure`; others → `UnknownFailure`.

Firebase applies its own sign-in rate limiting (`too-many-requests`, currently shown as the generic error).

## Cloud Firestore (`cloud_firestore`)

All operations; structures in [DATA_MODELS.md](DATA_MODELS.md); authorization in [SECURITY.md](SECURITY.md).

| Repository method | Firestore operation |
|---|---|
| `ProfileRepository.watch(uid)` | listen `users/{uid}` |
| `ProfileRepository.save(profile)` | `set(merge: true)` `users/{uid}` |
| `DiscoverRepository.fetchCandidates(me)` | query `users` where `teach` array-contains-any `me.learn` (≤30), limit 50; query `likes` where `from == me.id` |
| `DiscoverRepository.swipe(...)` | `set likes/{me}_{target}`; if liked: try `set matches/{pairId}` (rules accept only on mutual likes); on `permission-denied`, `get matches/{pairId}` to detect a match the other person created at the same moment. The other person's like is never read. |
| `MatchRepository.watchMatches(uid)` | listen `matches` where `userIds` array-contains `uid` |
| `MatchRepository.watchMessages(id)` | listen `matches/{id}/messages` orderBy `createdAt` desc limit 100 |
| `MatchRepository.sendMessage(...)` | batch: create message + update `lastMessage`, `lastMessageId`, `lastMessageAt` |
| `userProfileProvider(uid)` | listen `users/{uid}` (other person's name in Matches and Chat) |
| `ProfileRepository.createWithConsent(profile)` | batch: `set users/{uid}/private/consent` + `set users/{uid}` |
| `ProfileRepository.acceptConsent(uid)` / `watchConsent(uid)` | `set` / listen `users/{uid}/private/consent` |
| `MatchRepository.closeMatch(...)` | `update matches/{id}` → `status: closed`, `closedBy`, `closedAt` |
| `SafetyRepository.block(...)` | batch: `set blocks/{me}_{other}` (+ close the match if active) |
| `SafetyRepository.report(...)` | batch: `add reports/{auto}` + `set blocks/{me}_{other}` (+ close the match if active) |
| `DiscoverRepository.fetchCandidates` (addition) | also queries `blocks` where `blocker == me` to hide blocked people. All three queries are **server-first** (12 s timeout) with a cache fallback; offline with no cached candidates throws `NetworkFailure`. |

Error codes mapped: `permission-denied`, `unauthenticated` → `PermissionFailure`; `unavailable`, `deadline-exceeded` → `NetworkFailure`; others → `UnknownFailure`.

## Pagination, limits, timeouts, retries, cache

| Topic | Current behavior |
|---|---|
| Pagination | None. Fixed limits: 50 candidates, 100 messages. |
| Query limits | `array-contains-any` accepts ≤ 30 values (app sends at most 30). |
| Timeouts / retries | SDK defaults; Firestore retries transient errors internally. Failed screen loads offer manual retry; Riverpod 3 also retries failed providers automatically. |
| Cache | Firestore offline persistence (SDK default on mobile). Writes made offline are queued and synced later. |
| Quotas | Firebase Spark (free) plan quotas apply per project. |

## Configuration

`lib/firebase_options.dart` (generated by `flutterfire configure`) contains the project identifiers. These are public client identifiers, not credentials. No server keys or service accounts exist in the app.
