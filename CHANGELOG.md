# Changelog

All notable changes to this project are documented here. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed (responsividade e performance — 2026-11-21)
- Every screen audited at 320–1024 dp, phone landscape and notched landscape, with system text at 100/130/200 % (`test/responsive_matrix_test.dart`); report in `docs/audits/2026-11-21-responsividade-performance.md`.
- Fixed overflows: post/member/comment action sheets (now one scrollable `showActionSheet`), notifications app bar, chat menu, comment "Responder" row.
- Tablets and wide windows: content capped to a centered 720 dp column (`ContentWidth`), keeping state when the window crosses the cap.
- Bottom bar labels share one size (never below the default); profile header and button rows adapt instead of breaking words; Match card initials no longer grow with system text.
- `PersonName` helper replaces five copies of name parsing; chat time formatter cached.

### Added (Comunidade)
- Fifth bottom-navigation tab **Comunidade** (center): feed with filters Para você / Seguindo / Skills / Projetos, cursor pagination, pull to refresh, loading/empty/error states.
- Posts: text (≤ 2000), up to 5 images (resized to ≤ 1440 px, ≤ 300 KiB JPEG, EXIF/GPS removed, stored inline in `posts/{id}/media`), type, related skills, hashtags, preview, edit (text/type/skills/tags) and delete; idempotent publishing (no duplicates on retry or double tap).
- Likes (optimistic, one per member), comments with one reply level, saved posts (private), follows with counts and lists, share by link (`skillswap://app/post/<id>`, Android intent filter) or inside an existing chat, in-app notifications.
- "Quero aprender com …": reuses the Match flow (like + match attempt decided by the rules) with the post as context; shows interest sent / open chat.
- Member profile with stats, follow, message, skills and a portfolio grid; own profile shows the stats, "Minhas publicações" and "Salvos".
- Search: people (name prefix), posts (word or #tag), skills (who teaches it and related posts).
- Moderation: report post/comment (spam, harassment, offensive, scam, inappropriate, other), block from the feed/profile (also removes follows), admin custom claim for moderators.
- Security Rules for all new collections, anti-spam cooldowns (posts 30 s, comments 3 s), composite indexes (`firestore.indexes.json`) and 30 new rules tests.

### Added (Comunidade — vídeo)
- Short video posts: one MP4 (≤ 60 s, ≤ 2.3 MB) instead of images, stored in Firestore chunks (`posts/{id}/video/{0..2}`, Spark plan); location/device metadata removed before upload; poster frame as the post image. Player with poster, play/pause, scrubbing, mute and full screen; never autoplays; pauses when leaving the screen, tab or app; downloaded on the first tap and cached.
- New post type **Conhecimento** (`knowledge`).
- Rules: `validVideo`, all chunks required on create with sizes adding up exactly, chunks only in the post's batch and deleted only with the post, at most one video per hour per member (`rateLimits.lastVideoAt`, Spark storage quota); 12 new rules tests (123 total). 24 new Dart tests (192 total).
- Privacy: metadata stripping fails closed (refuses files it cannot fully walk, timed metadata/GPS tracks and leftover location markers; also clears XMP `uuid` boxes); the picker's original copy is deleted; downloaded videos are cached atomically with a 50 MB cap.
- `tool/seed_test_users.ps1`: sixth fictional account (Daniel Moreira, teste6) with an illustrated avatar.

### Security
- Firebase App Check (`firebase_app_check`): Play Integrity / App Attest in release, debug provider in development. Enforcement is a console step (docs/SECURITY.md).

### Changed (Comunidade)
- Blocking or reporting a person also removes the follows between the two.
- Report reasons gained "offensive" and "scam"; "Spam ou golpe" became "Spam".

### Changed
- App renamed from "Skill Suap" to "Skill Swap": display name (Android label, iOS bundle name), localized strings, wordmarks, Dart package (`skill_swap`), `SkillSwapApp` / `SkillSwapSplashScreen` / `SkillSwapLogo`, emulator project id `demo-skill-swap` and docs. Unchanged on purpose: the Firebase project id `skill-suap` (cannot be renamed) and the folder names.
- App identifiers: Android `applicationId` is now `com.skillswap.skill_swap` and the iOS bundle id `com.skillswap.skillSwap`, registered as new Firebase apps (`lib/firebase_options.dart`, `android/app/google-services.json` and `firebase.json` regenerated by `flutterfire configure`). The old `com.skillsuap.*` Firebase apps are still registered but no longer used; installed copies of the old app are a separate app on the device.

### Added
- Profile photo: pick from the gallery, center-cropped to a 384 px square JPEG with metadata (EXIF/GPS) removed, stored inline in the profile (`users/{uid}.photo`, works on the Spark plan). Shown in Discover, Matches, chat and profile; initials remain the fallback. Rules accept only a JPEG of at most 48 KiB; the app also rejects stored photos larger than 1024 px before decoding.
- `tool/seed_test_users.ps1`: 5 complete test accounts (`teste1@gmail.com` … `teste5@gmail.com`) with illustrated avatars, likes and a chat; replaces `seed_demo_users.ps1` and `new_test_accounts.ps1` (old test and demo accounts deleted).
- Email/password sign-up and sign-in (Firebase Auth) with validation and human error messages.
- Profile setup and editing: name, bio, skills to teach and to learn (20-skill catalog).
- Discover swipe deck: candidates who teach what you want to learn, ranked by mutual compatibility; drag or buttons; optimistic removal with rollback on failure.
- Mutual-interest matching with "It's a match" dialog.
- Matches list and real-time private chat.
- Firestore Security Rules for users, likes, matches and messages, deployed via `firebase.json`.
- Firebase project `skill-suap` configured for Android and iOS (`lib/firebase_options.dart`, `android/app/google-services.json`, Google Services Gradle plugin).
- Black / White / Lime Material 3 design system (tokens, dark and light themes, shared components).
- Portuguese and English localization (ARB), Portuguese as fallback.
- 15 automated tests (unit, repository with in-memory Firestore, widget).
- Documentation: README, `docs/` (architecture, features, screens, design system, components, API, data models, security, performance, setup, deployment, testing, localization), ADRs 0001–0003, contributing guide.

- `tool/run_android.ps1` (NDK install + emulator boot with software rendering + `flutter run`), `tool/install_ndk.ps1`, `tool/adb.ps1` (screenshots, tap by label, verified text fill), `tool/flow.ps1` (sign-up / sign-in steps), `tool/new_test_accounts.ps1` (git-ignored local test credentials).
- Real screenshots in `docs/assets/` and a manual end-to-end check record in `docs/TESTING.md`.

### Added (demo data)
- `tool/seed_demo_users.ps1`: 5 fictional people with complete profiles and consent, created through the normal security rules; two pre-like the test account Ana so matches can be demonstrated.

### Fixed (Match screen)
- Slow/offline network no longer shows a false "Ninguém novo por enquanto": candidates are fetched server-first with a cache fallback, and an offline empty result shows "Sem conexão" with retry (MS-10).
- Undo is available from the empty state after skipping the last card (MS-9).

### Changed (Match screen)
- Premium Match screen: logo header, glass card with real skills, "Match de conhecimento" banner computed from both profiles (exchange / teach / learn; hidden when nothing connects), round actions (undo last skip, skip with red X, approve with black ✓ on lime, save disabled), animated exits from buttons, horizontal-only drag, semantic swipe actions, undo slide-in. Removed the "% compatível" badge from the card. Notifications and save are shown disabled (features don't exist yet). 20 new tests.

### Added (opening)
- Animated opening `SkillSwapSplashScreen` with the brand logo (`assets/branding/logo.png`): fade/scale entrance, subtle pulse with lime glow, growth, then a fade + slide reveal once startup is resolved; holds discreetly on slow startups; honors reduced motion; never shows protected screens early (router unchanged).
- Native launch screens are now solid black on Android (including Android 12+ system splash, transparent icon) and iOS — no white flash.

### Security
- H1 user safety: 18+ / terms consent required to create a profile (consent screen for older accounts), terms screen, unmatch, block (prevents new matches and messages), report (write-only, also blocks and closes the match) from chat and Discover; 26 new rules tests (66 total) and 13 new Dart tests (32 total).
- Security audit recorded in `docs/audits/2026-11-20-security-audit.md`.
- Firestore rules hardened: likes private to their author (no more learning who liked/skipped you); exact field lists everywhere; server-time timestamps; skills restricted to the catalog; user listing limited to 50 per query; outsiders cannot probe matches; match preview must mirror a real message created in the same batch.
- Matches no longer store names (spoofable); the app reads names from profiles. Unknown skill ids are dropped on read.
- 40 Security Rules tests on the Firestore Emulator (`firestore_rules_test/`); Dart tests 15 → 19.

### Fixed
- Localization delegates now use the `material_ui` / `cupertino_ui` localizations; the generated defaults would have crashed every text field with "No MaterialLocalizations found".
- Android release builds now declare the `INTERNET` permission (the template only had it in debug/profile).

### Known issues
- Full flow (sign-up → profile → discover → match → chat) verified manually on the Pixel 8 API 36 emulator; not yet on iOS or a physical device. No performance measurements.
- Security Rules not tested with the Firebase Emulator.
- Release signing, account deletion, push notifications, report/block not implemented.
